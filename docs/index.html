Structural fingerprints for Go/Java codebases

beats

Every codebase develops structural habits — recurring shapes in how functions are written that no one named but everyone follows. Beats finds those patterns and surfaces the functions that don't fit them, with the exact delta

How it started

It started with a simple question and a case study to keep me busy.

I am fascinated by shapes; they intrigue me. A visual imprint can become so clear and ingrained that it can help you navigate in the dark. So naturally, I was like oooohh! Does this happen for codebases as well? And thereby: does vocabulary-independent clustering find real patterns in real codebases?

Explore the reports below to see what that looks like across real OSS codebases.
